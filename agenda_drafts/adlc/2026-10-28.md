### 5. NVIDIA Secure Agent Workspace reference design, and the ADLC (15 min)

**Proposed lead:** Matthew Gladney (NVIDIA), with Emrick Donadei.

**What it is.** A [reference design](https://docs.nvidia.com/enterprise-reference-architectures/secure-agent-workspace-reference-design/latest/index.html) for running agents in a managed workspace instead of on the employee's laptop. The laptop, IDE or terminal is only the interface. The agent runs in a company-managed VM. Described in the [NVIDIA technical blog](https://developer.nvidia.com/blog/how-to-govern-autonomous-agents-in-enterprise-ai-factories/) (June 29, 2026) and last updated October 21, 2026, alongside the [OpenShell Reference Architecture](https://nvidianews.nvidia.com/news/openshell-reference-architecture) announcement. Reference implementations exist for Red Hat OpenShift and Microsoft Azure.

- **Phase I, perimeter:** one VM per user, SSO gate, outbound traffic denied by default, human approval for actions that change state, central logging.
- **Phase II, runtime:** an OpenShell sandbox, signed policy bundles, a credential proxy so the agent never sees raw secrets, and a check before every action.
- **Seven planes:** user endpoint, control plane, bootstrap plane, access management (trusted access broker), agent workspace, safe runtime, and enterprise services. Audit is sent as OCSF events from outside the agent process, which the agent cannot turn off.

**How it maps onto the paper's phases:**

| ADLC phase | What the reference design provides | What the ADLC adds |
|------------|-------------------------------------|--------------------|
| 3.1 Scoping and design | Rules for which actions need human review. A delegation record for each engagement | The design record that these settings should trace back to, and owner approval |
| 3.2 Supply chain | Approved VM images only (golden images, GitOps profiles). Inference through a gateway | Trust tiers for models, tools and retrieval sources, not only the image |
| 3.3 Development | Policy intent kept in Git and released as signed bundles | Matches "policy surface at parity with code". A good worked example |
| 3.4 Admission | Sandbox creation, policy changes and image upgrades are operator actions on the control plane, never agent requests. Agent identity is registered against an SSO sponsor | The sponsor maps to the accountable owner (§2.4). The ADLC also requires a behavioral baseline at admission |
| 3.5 Runtime | Sandbox, outbound allowlist, credential mediation, checks before each action, OCSF audit, optional out-of-band DPU monitoring (NVIDIA Sentry) | A strong example of containment posture. Behavioral baseline and drift (RFC-195) sit on top of its telemetry |
| 3.6 Reflection / 3.7 Maintenance | Workspace rebuilds and image upgrades. The docs describe "three timescales of sandbox lifecycle" (not reviewed yet) | Memory and knowledge consolidation are not covered. Re-check the threat model when policy or images change |
| 3.8 Decommissioning | An admin kill switch for broker sessions and revocation propagation. The docs say stopping execution does not by itself revoke downstream authority. The maximum revocation delay is left open | **The same point as the paper's §1.1.5.** Teardown with evidence, plus residue (memory, webhooks, sub-agents) that the design does not cover |

**Questions for the room:**

1. **Cite it, or use it as a worked example?** §2.1 says the paper is "a process framework, not an implementation guide". The cleanest fit is a short worked example in §4 ("Applying the lifecycle"), next to the containment paper citation in §2.2.
2. **Overlap with the containment paper** (PR [**#262**](https://github.com/cosai-oasis/ws4-secure-design-agentic-systems/pull/262), Jeff Leva). The safe runtime and network boundary planes are containment. Should the ADLC point to the containment paper, and the containment paper cite this design?
3. **Vendor neutrality.** CoSAI papers stay vendor-neutral. If we cite it, cite it as one example of a managed agent workspace, with at least one other example.
4. **Gaps we could send back.** Decommissioning (the open revocation delay and residue), and the behavioral baseline. Would NVIDIA take feedback from the SIG on these?
